05 · Opencode 簡介

OpenCode 是什麼？

開源 AI 編碼代理 · 美國製作

定義：OpenCode 為開源之 AI 編碼代理（AI coding agent），可於終端機、桌面應用程式、VS Code 及網頁介面中，串接大型語言模型，協助撰寫、閱讀及修改程式碼。

  • 開發團隊：美國 Anomaly Innovations, Inc.（舊金山，品牌 Anomaly / anomalyco）。
  • 公開資訊：官方網站 opencode.ai、GitHub anomalyco/opencode（MIT 授權）。
  • 核心特性：支援 75 種以上模型供應商、本地模型部署、團隊版 Zen 及多元 IDE / CLI 整合。
  • 產製地區：服務條款與隱私權政策載明主體為美國企業，準據法為美國德拉瓦州，非中國製產品。

來源：opencode.ai、/docs/models、Terms、Privacy、GitHub

為何本研習納入此工具？
開源可驗證

程式碼公開，更新頻繁，社群活躍度高。

不綁定單一模型

可介接 GPT、Claude、Gemini 及開源模型。

適於資料處理

可批次讀取表格、轉換格式、繪製圖表及產製報表。

可本地執行

搭配本地模型，降低敏感資料外送之風險。

💡 縱使工具於本地端執行，若串接雲端模型，提示內容仍可能經網路傳輸；各類模型均可能蒐集資料以進行分析。

🎯 核心提醒
OpenCode 本身為 美國 Anomaly 團隊所開發之開源專案；惟其所串接之模型分屬不同國家與企業，選用時應審慎評估資料流向。

10 · 資料去識別化

資料去識別化 — 分析前之必要程序

工具：SAAA 學生學習能力檢測去識別化工具 v2.0 · 100% 本地端運算 · 零個資上傳 · 依現行個人資料保護規範辦理

圖：SAAA 去識別化工具 v2.0 介面 · 以此截圖為準 · 開啟工具 →
1選取或拖入評量檔案 / 資料夾 / Zip

將「個人成績」「作答反應」「班平均」「答對率」或整體評量目錄，以拖曳或選取方式匯入。支援單檔、多檔、整體資料夾及 .zip 壓縮檔批次處理。所有檔案於瀏覽器本地端解析，不經網路傳輸。

2選擇去識別化模式

依資料用途擇一辦理：
研究分析模式（推薦）：學生姓名轉為跨表一致之匿名代號（如 STU_112_0001），自動產出 mapping_table.xlsx 對照表供校內留存，座號移除並對校名、縣市採脫敏處理；
公開資料模式：徹底刪除姓名與座號單位，校名與縣市脫敏且不保留任何逆對照表，適用於對外公開；
校內避難模式：姓名採規則遮罩（如 林*成），保留原始欄位與座號結構，適用於校內教學研討。請審慎擇定，一經產出難以回溯。

3機關別名與參數微調

設定「學校替換名稱」「學校代碼別名（如 SCH01）」「縣市替換別名」、座號欄位處理（移除座號 / 保留）及檔案輸出格式（Excel + JSON 雙格式）。參數應與校內行政一致性核對，確認輸出內容無殘留可識別資訊後，再行進入後續 AI 分析流程。完成後點選「開始執行去識別化並打包下載」取得已處理之資料集。

嚴正提醒：未完成去識別化之原始檔案，不得上傳至任何雲端模型或對外發布。對照表應由專責人員妥善保管，不得與去識別化後資料一併流通。

16 · 年級：發生什麼？

五年級（七年級）整體發生什麼？

Prompt｜先說證據，不急著給建議
幫我分析五年級目前最值得注意的三個現象，請先說資料證據，不要急著給教學建議。

觀察四個面向

  • 整體表現？
  • 班級差異？
  • 能力向度？
  • 共同問題？
如果是你，你第一眼會先看哪一個？
17 · 班級：問題集中在哪？

全年級的問題，每個班都一樣嗎？

Prompt｜比較班級與年級
請比較各班與年級整體，找出一個最值得進一步下探的班級，並說明為什麼。不要只依班平均高低判斷。

不要只看平均

還要一起看班級與年級的差距、共同失分題、能力向度與作答型態。

班平均告訴你「哪裡不同」，題目與能力向度才開始告訴你「差在哪裡」。
18 · 題目：到底錯在哪裡？

低分還不夠，我要知道學生錯在哪

Prompt｜找出最值得先看的題目
在這個班中，找出最值得教師先查看的 3 道題，說明本班與年級的答對差距、共同失分情形，以及有選項資料時的主要錯誤反應。

每一道題都要有證據

  • 本班與年級的答對差距
  • 是否為共同失分
  • 錯誤選項集中情形
題目診斷的目的不是排名，而是確認可能的迷思概念或錯誤策略。
19 · 分組：為什麼這些學生放在一起？

分組不是把學生分完就結束

Prompt｜建立有證據的教學分組
請建立這個班的教學分組。每一組都要先說明「為什麼是這一組」，列出本組平均、與全班差距、優先確認向度、共同失分題與作答型態證據，再提出不同的教學活動、教師提問與成功判準。

分組之後還要回答

  • 為什麼是這一組？
  • 要做什麼不同活動？
  • 如何判斷學會了？
你有沒有發現，兩組的教師提問不應該一樣？
20 · 個人：同一組學生也不完全一樣

最後才下探到個人

Prompt｜挑一位有代表性的學生
請從這個班挑一位具有代表性、值得進一步了解的學生，不必挑最低分學生。說明他的整體表現、優先確認向度、代表性失分題與作答型態，最後提出一週內可以執行的微型教學介入計畫。

個人輪廓不是貼標籤

選擇具有代表性的學生，目的是把班級層級的發現轉成可執行、可追蹤的一週介入。

順序很重要：先看年級與班級，再看題目與分組，最後才下探到個人。
21 · 進步／退步分析

年度差異要分清楚：觀察、解釋、待確認因素

Prompt｜比較 115 年與 114 年
請比較 115 年與 114 年五年級的學力結果，找出主要進步與退步發生在哪些科目、能力向度、班級與題目。請分成「資料直接觀察到的結果」、「資料支持的合理解釋」與「仍需其他證據確認的可能因素」，並提出下一步值得追蹤的教學重點。不要把年度差異直接解釋成因果。
追問｜如果只能先處理一件事
如果只能優先處理一個退步現象，應該先處理哪一個？為什麼？
提醒：不同年度通常是不同學生群體；年度差異可以描述，但不能直接視為個人成長或因果證據。
22 · 收尾：最後才建立 Dashboard

把剛才的分析整理成一個 Dashboard

Prompt｜整合分析結果
請把剛才完成的年級、班級、題目、教學分組與個人分析整合成教師版 `dashboard.html`。保留資料證據與教學行動，讓使用者可以從「年級 → 班級 → 題目／學生」逐層下探。

Dashboard 的結構

  • 年級：發生什麼？
  • 班級：問題在哪？
  • 題目／學生：如何下探？
  • 教學行動：下一步怎麼做？
Dashboard 並不是 AI 隨便畫一個網站，而是把剛剛一步一步完成的分析整合起來。
